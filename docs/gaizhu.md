# 盖主速刷

独立插件 `gaizhu`，当前 `0.1.11`，最低核心 `0.5.62`，入口「自动 → 盖主速刷」，前置为百胜战功插件。随当前核心构建提供，也可从本地市场单独安装。无需旧小抄或旧拓展。

## 使用

1. 两个账号手动进入同一自建身份房。小号作为房主／主公，大号作为反贼；先确认房间规则、身份和人员。
2. 小号选择「盖主小号」，按需要开启「等1分钟」，点击「开始速刷」。插件将黄盖写入主公槽并通过原生入口提交，不打开点将卡窗口；随后补普通小杀、开始并选黄盖，再连续使用苦肉及拒绝求桃。首次等待房间会先检查并修正下述设置。
3. 大号选择「反贼大号」，选择百胜点将方式，点击「开始速刷」。插件准备、开局选将，拒绝手气卡并经过守备期后托管。
4. 点击「停止速刷」立即停止本端自动操作。折叠面板和切换工具箱分类只隐藏界面，运行仍继续。

开始代表授权本端执行上述游戏操作。房间点将和反贼点将可能消耗游戏点将卡等资源，开启前请确认。不能同时运行旧小抄／拓展的自动挂机或盖主速刷；核心隐藏旧界面并不保证旧后台已停止。

运行开关仅保存在内存；安装、刷新、插件停用／重新启用、重载、升级或回退均不会自动开跑。点将方式和延时偏好按账号保存，切号立即停止并读取新账号偏好，不导入旧拓展的全局运行开关。不会自动创建房间、登录其他账号或代替另一端操作。

## 房间设置检查（0.1.10）

仅盖主端在每次手动启动后的首次等待房间检查一次；停止再启动才重新检查。每局结算返回房间不复查，不轮询规则，反贼端和对局中不检查。

- 必须是身份演武（应变或军争）且当前账号是房主；不符合或无法确认时在 HUD 报错停止，不点将、不补人机、不开始。
- 密码按字符串处理：保留任意合法的1–4位数字密码，但拒绝精确的 `1`；`01`、`001`、`0001` 均保留。无密码或不合法时生成4位数字密码。HUD 明文显示已确认的密码，可复制；不长期保存密码。
- 自选身份（5）、自选主忠（6）、自选反贼（7）均保留，其余改成自选身份。关闭手牌构筑，关闭禁止点将（允许点将）。
- 所有修正合并提交，等待服务器成功事件后才继续点将。被拒绝时等待5秒再重试，最多提交3次；重试沿用同一密码，不重新检查整套设置。连续3次被拒绝或单次提交6秒未确认即停止。等待中 HUD 显示重试状态，不点将、不补人机、不开始；停止、切号或停用即取消，重试前核对仍在原等待房间且仍是房主。原房间对象和无关规则保持原值，请求使用独立副本。

接口依据同一官方缓存：模式显示判断 6670641、位置模式常量 4277371、设置窗口原生模式 getter／规则副本 20366600 附近、原生请求工厂 20376500 附近、成功事件 8278231。通过已注册 `CreateTableWindow` 的 getter 和无控件请求工厂访问闭包接口，不创建窗口、不改原生控件。REA 全文件分析因解析堆限制未完成；上述依据是缓存文本的定点静态核对，未证明当前官服版本一致。

## 规则

- 主公点将使用槽 `0`，反贼使用槽 `2`；确认回包 `Figure` 分别为 `1`、`3`。
- 不点将：不写反贼槽，从开局候选优先挑未完成百胜的武将；框中没有可用进度时按旧逻辑回退选将。反贼排除名称含「黄盖」的变体。
- 随机点将：在已拥有、未完成百胜的可用武将中随机选取；原槽中的武将尚未完成时继续使用，完成后轮换。
- 按序点将：技能战功已完成优先，其次百胜进度较多优先，并列按武将 ID 排序。每局重新提交点将，结算后刷新战功。
- 等1分钟：沿用拓展的近似节奏，前45秒等原生倒计时剩3秒再苦肉，45秒后取消延迟。它不保证每局精确持续60秒；无法读取倒计时时不会伪造剩余秒数。
- 苦肉两次操作至少相隔600毫秒，单局最多40次；选将、开始和托管都有有限等待／重试。不能识别、失败和未确认会显示状态或完整错误，不把本地点将写槽当作服务器成功。
- 仅在速刷运行时处理手气卡；只拒绝／关闭手气卡提示，入局20秒、选将后10秒以及刚见手气卡的守备期内不主动开启托管。

### 0.1.3 历史窗口补齐（已由0.1.4替代）

核对拓展 2.6.8 的实际调用链：房主入口（6842）与反贼入口（8290）均调用 `gzEnsureDianjiangGeneral → gzDianjiangSelect → gzDianjiangRun → gzDianjiangSend`，本次没有整段导入历史模块。

恢复这条链中遗漏的窗口处理：已挂载的隐藏窗口直接复用，脱离显示列表的缓存窗口不发送；写槽时仅在已有窗口时发送身份页事件；提交后优先 `Remove(true)`、必要时 `removeSelf()` 并隐藏，重新写槽保存；临时出现的点将界面按可见性快照隐藏，停止与释放也清理。回包兼容 `data/generalId` 字段。继续保留现有明确点将上下文确认、发送前槽位校验和插件取消机制；没有将未发送的本地槽位报告为服务器成功。

当时单测覆盖隐藏窗口复用、原生 Remove 清槽后重新保存、缓存窗口排除、停止时隐藏临时界面；这些窗口流程建立在错误模拟上，不能作为0.1.4直接提交的依据。离线验证不代表官服实局验收。

相关单测：`node --test tests/gaizhu*.test.js tests/plugin-independence.test.js`；契约／打包：`npm run check:plugins`、`npm run build`；独立浏览器演练：`npm run test:browser-gaizhu`。

盖主速刷 0.1.1 起要求核心 0.5.62，并以前置插件 `baisheng`（百胜战功）作为启用条件。请先安装并启用百胜战功，再启用盖主。核心 0.5.74 起更新百胜战功时会自动暂停已启用的盖主，更新成功或失败恢复旧版后自动重启盖主；原本停用的盖主不会被启用。停用、卸载、手动重载或回退百胜战功仍需先停用盖主。

### 0.1.5 添加人机与拒绝询问修复

添加小杀优先调用原生按钮 onMouse 点击分发，避免继承 onClick 静默无效；自动确认当前普通小杀选项，空位未补齐时不发起开始。手气卡优先调用游戏内弹窗关闭接口（包括该弹窗实例的 close），没有接口才点击明确拒绝按钮，绝不使用手气卡。濒死询问补齐 spellSelector 的取消选项及按钮栏直接取消控件。

验证：54项盖主测试通过，17个插件契约检查通过，0.1.5独立包与本地市场已构建。新增回归覆盖静默失效的添加按钮、空位阻止开始、弹窗关闭优先于回调和濒死取消。未进行官服实局验证。

### 0.1.6 主公黄盖点将成为开局硬条件

验证：57项盖主回归、17项插件入口契约检查及构建通过；新增覆盖写槽失败、提交清空、没有服务器确认、确认后清空、添加人机后清空及黄盖ID缺失。未进行官服实局验证。

### 0.1.7 求桃取消不再被累计次数及技能选择器阻断

### 0.1.8 按截图中的原生按钮栏执行濒死取消

根据用户截图的「出桃或酒你可回复1点体力」，主公当前可见按钮栏的濒死提示优先于选将/手气卡缓存窗口处理；取消先调用按钮栏 Button_Click(button)，保留原生 CanOperationInGame、GM事件、禁用按钮及 ApplyButton 回调流程，避免按钮自身 onClick 的 autoReset/selected 门禁；无此入口时保留旧按钮点击。普通取消也优先按钮栏，识别带空格的「取 消」。不选择桃/酒，不直接发送协议。

### 0.1.9 修复按钮栏错误依赖旧脚本别名

用户截图显示实际求桃提示可见，插件状态却进入「等待苦肉可发动或当前询问结束」。核对缓存官方脚本发现 SelfSeatUi.createGameBar 将 Xzt 保存在 this.Pt（字符17136702附近），整份缓存未出现 buttonBar 字符串；此前实现和演练均依赖旧 buttonBar 别名，导致仅运行工具箱时读取不到实际按钮栏。现在限定读取原生 Pt，兼容旧 buttonBar；取消、濒死文案及匿名手气卡共用该解析入口。支持原生 ButtonCancel getter。

验证：62项盖主测试通过，含完全不提供buttonBar的Pt求桃取消、取消后继续苦肉、停止后不操作、Pt优先于旧别名和Pt手气卡拒绝；真实核心adapter演练也移除buttonBar字段。17个入口契约及0.1.9包/本地市场构建通过。此为缓存官方脚本和离线执行证据，未操作官服实局。
