# 玩家信息 0.3.3

独立插件 `player-info`，最低核心 0.5.0，无前置、无设置、无持久化、无上传。随插件启用生效，停用释放轮询、主题订阅及提示，不修改核心源码或版本。

采用个人页的 `ClientId > 0xee6b2800`（4000000000）规则。此为账号范围启发式，不能保证官方后续账号分配仍满足该规则。缺失、非法 ID 不判断；等于边界不提示，不根据昵称猜测。不移植隐藏战绩按钮及其他个人页行为。

每250ms检查已有显示树中的可见 UserInfoView，仅遍历非场景显示子节点，最多512项，不创建窗口、不包装原型。个人页打开或目标变更且资料已到达时，在画布顶部显示“这是个人机”5秒。关闭重开会再次提示。开局读取现有座位 playerInfo/PlayerInfo.ClientId，发现符合账号规则的玩家显示“人机对战”8秒；资料延迟时继续等待。按场景与核心 session 去重，同场景连局由 session 重置。启用时正在进行的牌局也会检查一次。

提示为游戏画布顶部的 HTML 覆盖层，不拦截鼠标，随画布位置、尺寸与主题更新。切换账号清理旧提示；退出牌局不持久化对局资料。无画布时不显示。

## 自选身份演武

身份演武（73）及军争演武（74），仅限 IsChooseFigure 为 true 的完整八人房。按房间原始 datum 顺序映射主公、忠臣、忠臣、内奸、反贼、反贼、反贼、反贼，再按玩家 ID 匹配战斗座位；不使用战斗 UI 排列或行动顺序代替房间顺序。直接调用现有 figureManager.SetFigure 填入空白身份，不添加额外文字或标签，不修改 seat 身份数据及核心。已确认或已显示的身份保持不变。

要求房间及牌局名单各八个唯一有效账号且集合一致；名单缺失、重复或不匹配时不填。恢复对局、消息缺口、回放及其他模式不填。使用已存在的 RoomControler 或现有 ServerProxy 的限定协议调用者（20508/21208）恢复房间控制器，不创建单例。快照缺少模式时，按客户端 TableSimpleId 使用的房间 ID 编码读取模式。

停用、退出、切换场景、切换账号或本局 session 重置时，释放实例方法包装，并只还原仍由本插件拥有的填充。游戏后续调用 SetFigure 即交还控制权，即使新值与填充值相同也不会在停用时清空。身份结果仅在当前运行期使用，不保存账号名单或身份历史。

## 0.2.1 个人页正常而身份未补全的接入修复

修正房间控制器发现入口：原生 ServerProxy.AddEventListener 将20508映射为 ClientTableinfoRep，将21208映射为 GsCModifyUserseatNtf；它在 Laya 事件表中使用精确协议名称，不使用数字键。此前入口的大小写不一致，且数字兜底不能覆盖该真实调用链。现在优先读取这两个真实名称，保留已有兼容入口，不改核心。

## 0.3.0 玩家侧边三行资料

仅在原生排位132、普通斗地主148/149、单骑160显示和查询。其他原生模式（含自由欢乐22、身份演武、赛事、扑克牌斗地主）不新增资料查询或信息卡；已有的人机提示与自选身份功能保持原有范围。新增资料不持久化，无上传、云同步或战绩跳转。

第一行保留玩家账号 ID，官阶借用原生 otherTopManager.officerBg/officerIcon 的现有贴图及 officerText 的内容、字体；贴图由游戏加载和拥有，插件不销毁它们。机器人改为线性机器人图标，不请求其战绩。尚未就绪的官阶显示未知。

第二行：斗地主与单骑请求原生近100场表（Tab9和12），按客户端统计的 WinCount/TotalCount 显示胜率；斗地主地主、农民合计计算，不对两种身份胜率取平均。少于100场按返回的实际场数，不假装有100场。排位使用当前赛季 curCycData.curRecord 的胜负场，按原生个人页使用的本赛季 maxLevel 和 star 展示段位星数。段位名称读取官方 mod_new_ttrank_config 的 RankLevelCfg.Item 及 Common.xiaoxiongShow 星数分段，不硬编码枭雄名称。

第三行：分别请求 RecordId26/35/44 的近期记录，只读取 GameOverTime、GameResult 等必要统计字段，按结束时间降序计算当前连胜或连败。0为胜、1为负；平局或未知中断连续段。返回列表全部为同一结果时显示“至少N连胜/连败”，避免把历史边界当成确定长度。资料缺失、失败、无记录显示未知/等待，不能显示0%或虚构连胜。

请求复用已存在 UserInfoManger（通过 ServerProxy.ClientGameRecordInfoRep 的 caller 定位），调用原生 SendClientGameRecordInfoReqByTab 和 SendClientGameRecordInfoReq。排位调用当前 UserData 类的 SendUserTTDateReq，并监听 ClientTTRankInfoRep，投影当前赛季最小字段。每400ms最多一次资料请求，每次场景/账号/session内每个查询键只提交一次，不重叠重试。客户端百场表自身的180秒缓存规则保留。退出、账号切换或session变化清除本插件记录与监听；延期排位回调在代际不一致或停用时丢弃。查询异常不自动重复发送。

布局使用实际头像显示对象的 localToGlobal 和裁剪范围，兼容缩放；无法取得头像坐标时不猜位置。按左右可用空间选择信息卡，读取实际 otherTopManager.handCardSpr 及展开的 proptip 边界，避让竖向队友手牌条；另保留头像下方横向手牌区。空间不足时缩窄至210/190，仍无无碰撞位置则暂隐藏。排位队友在左/右都不按号位写死，按截图复核了上方、左右、右下自己布局；斗地主按地主和左右对称农民视角演练，用户纠正后的2/3号位称呼不影响坐标算法。

## 0.3.1 昵称与排除本人

当前第一行改为昵称＋游戏官阶（机器人为昵称＋机器人图标），不展示用户码。优先读取 NickNameForLocal，缺失时读取已有昵称字段，仍缺失则显示“昵称未知”，不退回用户码。本人按当前账号 ID 或原生 IsSelf 标记排除，在任何资料请求前跳过，因此不显示自己的信息，也不请求自己的百场、近期和排位赛季资料。布局仍保留自己头像与手牌条的避让边界。其余三行口径及模式白名单保持。

## 0.3.2 隐藏战绩与信息卡打磨

修复两个本地可复现的缺口：此前连胜计算拒绝全部缺失或为0的结束时间，且只读 RecordId 近期缓存。现在监听原生 ClientGameRecordInfoRep 并投影 Uuid/Tab/RecordId 与最多100条 GameOverTime/GameResult；近期缓存无可用连续结果时，使用同模式百场结果。三种模式都会获取 Tab1/9/12 的近期结果，排位显示胜率仍使用本赛季资料，不改成百场胜率。没有向服务器返回空结果的查询盲目重试。

时间完整时按时间降序；原生记录全部省略时间或为0时保留客户端展示使用的原生列表顺序计算。此分支只接收原生缓存/协议记录，不把任意无序导入当作最新顺序；部分记录有时间、部分缺失时仍保留未知。边界未找到则显示至少N连胜/连败。服务器确实没有返回胜负时显示“近期战绩未读取”，不伪装成0连胜。仅凭截图无法确认官服具体缺失字段，本次修复通过结果脱敏资料回放验证，不能据此宣称官服读取成功。

## 0.3.3 官阶文字配色与透明底板

官阶文字按用户指定：骁卒/校尉/郎将/偏将军为灰色；将军/上将军/国护军紫色；卫将军绿色、车骑将军蓝色、骠骑将军紫色；国都护经用户确认使用金色；大将军/大司马红色。未知名称保留主题次要文字色，不按昵称或不明数字猜官阶。浅色主题使用同色系较深文字，深色主题使用较亮文字，保留原生官阶名称与图标，不只靠颜色表达等级。移除座位控件灰棕背景，不修改或销毁原生贴图。

信息卡背景单独使用76%不透明度（24%透出游戏），文字、官阶徽章与机器人图标保持100%不透明。仅修改插件自有背景Sprite，不改变整个面板或游戏画布透明度。

修复玩家资料只显示合计胜率的遗漏：普通斗地主148/149继续显示近百场合计胜率，新增一行客户端百场资料的 DiZhuWinRate / NongMinWinRate，分别标为地主胜率、农民胜率；保留昵称官阶和连胜败。缺失或非法百分比显示未知，合法0%正常显示，不从总胜率推算身份胜率。无新增请求、设置、持久化或上传；稳定ID、最低核心及前置保持不变。斗地主卡片增高至110px，沿用头像及手牌避让，其他模式保持86px。
