浮卡图标可悬停查看中文含义，提示不拦截点击；画布外另保留供无障碍读取的完整原文。HTML 图标有中文 alt/title。素材均内嵌，无运行时远程下载，也不逐图扫描原生 loader 缓存。只释放插件自己的纹理；失败时保留语义文字，清理待绘制监听。

## 卡顿原因与修改

没有在此次布局路径中发现死循环。冻结版本在进入或返回地图时同步完成多轮搜索；三个完整卡片的七种宽度模型可检查约 28,000 个候选，再进行整组安排。真实浏览器基线中，文字 typeset 只占少部分，主要阻塞来自同步布局与绘制准备。

1. 预计算节点保护矩形、中心和合并区域；减少候选检查的重复对象/字符串分配，提前结束已经失败的同类检查。没有删除候选或放松硬条件；固定基线的候选数量、拒绝诊断、扩展数量及最终布局逐项相等。
2. `createPlacementTask` 使用与同步 `placeCards` 相同的生成器。调用方按帧推进短工作片，可以取消；只有完整复核后的结果才会提交。目标片长不是严格实时承诺，单次原生排字、排序或 GC 仍可能超过预算。
3. 渲染器每次只维护一个任务。尺寸、内容、场景或停用状态改变时撤销旧任务，提交前再次采集几何并核对签名。覆盖 A→B→A、战斗返回、旧 COMPLETE 回调、RAF 与定时器取消。
4. 用单一 scoped Laya Text 测量完整内容，缓存有界的文字尺寸和各宽度排版描述。测量时不创建卡片树或背景纹理，仅为最终选中的位置创建显示对象。图标解码不重新触发布局搜索，普通点击不重复计算。

## 性能证据与边界

环境：真实 Chromium + Laya core，使用官方八城 PNG、头像和擂台的本机合成场景。每档 CPU 速率各三个新页面试验，以下为三个试验的中位数，单位毫秒。

| CPU / 操作 | 原最大帧间隔 | 新最大帧间隔 | 原完成耗时 | 新完成耗时 |
| --- | ---: | ---: | ---: | ---: |
| 1× 首次进入 | 159.7 | 69.5 | 284.1 | 289.2 |
| 1× 战斗返回 | 131.9 | 7.0 | 179.0 | 220.5 |
| 1× 热场景重建 | 118.0 | 7.1 | 206.9 | 236.7 |
| 6× 首次进入 | 1284.7 | 361.2 | 1859.0 | 1945.6 |
| 6× 战斗返回 | 1208.4 | 20.8 | 1265.3 | 978.7 |
| 6× 热场景重建 | 1263.9 | 20.9 | 1357.9 | 1095.5 |

分片主要改善交互期间的长阻塞，不保证全部卡片更早完成。首次进入的整段时间包含原生素材解码、场景初始化和首帧；最终 6× 试验中的 145–221ms 原生长任务发生在调用插件 update 之前。插件 update 之后的冷入最大帧间隔中位数为 62.6ms，单个工作片峰值中位数为 46ms，首次排字/解码仍有短突刺；1× 对应最大帧间隔为 7ms。不能把整段冷入的剩余卡顿都称为已消除。
