# 山河战斗背景调查与开关

## 原因

本机官方客户端缓存 `C:/Users/Admin/AppData/Local/Temp/sgs-client/game/sgsGame_a.sgs` 中，注册名 `RogueLikeGameScene` 对应 `_8t`，继承普通战斗场景 `Dqt`（`TableGameScene`）。

山河场景覆写 `onWallPaperChange`：读取当前战斗配置 `Fight.UseBg`，缺省取 24，通过 `BACKGROUND_USEDID_GOT` 直接切换背景；没有战斗信息时才尝试城池 Scene 或父类方法。`UpdateBaseInfo` 在等待战斗 ID 时还会再次触发此流程，所以仅在进入后手动切一次背景，仍可能被后到的战斗数据覆盖。

缓存 `hd_roguelike.sgs.json` 的 Fight 表中，当前记录的 `useBg` 全部为字符串 `24`。这解释了不同关卡总是显示同一原生背景：正常背景选择流程被关卡指定背景覆盖。该路径不调用保存背景选择的 setter，不能据此认定用户保存的背景设置被改写。背景 24 在当前账号皮肤窗口中的名称和排序未进行实机确认。

普通战斗 `onWallPaperChange` 优先处理天气背景，否则走 `OnNormalWallPaperChange`，再由原生背景管理器处理模式规则、已保存选择和可用性检查。山河大地图、章节小地图另有自己的图片/动画流程，与此战斗背景覆写不同。

REA 静态分析证据 `ev_cd3d59c7f0753c9d50c2551b2b52ae40bfec59dca96a173cf1cde8cb0aca8a71`；只分析本机缓存的指定场景及背景管理器，不执行官方客户端，不分发其代码。静态观察不能代替当前官服实局确认。

## 使用

山河图插件 **0.2.16** 的“显示设置”新增“**保留自选战斗背景**”（当前试用版 **0.2.23**），默认关闭。在战斗中或尚未加载地图数据时也可调整；0.2.23 按用户最新思路改为进场后官方重选，下面的旧版拦截记录仅作历史。

- 开启：进入山河对局后，等待官方重选及图片接收监听就绪，再调用当前场景在 `SELECT_WALLPAPER` 登记的官方处理器，读取并应用原生保存的选择。通常进场后 1 秒触发；观察到背景加载完成时改为等待 150ms 再触发。
- 状态显示“等待官方背景入口”“等待对局背景就绪”或“已触发官方背景重选”。后者只表示已调用处理器，不等于图片/动画已成功显示；异常详情完整保留。天气期间推迟执行。
- 关闭或停用：取消待执行任务、移除自有事件监听，保留当前已经显示的背景；不主动切回默认图。默认背景和场景/背景层原生方法保持原样，不写原生背景持久设置。
- 每次重新进入山河对局、同实例收到新的轮次/战斗 ID 时重新触发。普通战斗、单骑无双、地图不执行重选；原有跨模式战法计数不受影响。
