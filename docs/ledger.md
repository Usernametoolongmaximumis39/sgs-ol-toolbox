# 本机账本

2026-11-15：`ledger` 0.3.0，最低核心0.5.142，位于「信息 → 账本」。独立安装，无其他插件依赖，无云端同步、登录云服务或上传接口。

## 背包搜索与抵价券角标（0.3.0）

- 启用账本后，在原生背包顶部增加道具名称搜索框和搜索／清空按钮。输入即筛选当前分类，忽略名称中的拉丁字母大小写；保留旧小抄的名称包含匹配规则。清空恢复当前分类全部物品，切分类保留关键词；零结果显示明确说明。背包打开时可用 Ctrl+F 聚焦、Enter 搜索、Esc 清空。
- 抵价券右上角显示“使用门槛-减免金额”，例如 `7000-2000` 表示满7000减2000。依据客户端的 `TypeID=98`、`usedeffect` 中的 `GRmb-AID` 和官方 `gn_dbs_coupon_cfg.sgs → sgs_config.couponsys.GRmb.seting[].AVV`，顺序与原生 `GetValue(0/1)` 一致。配置未就绪、未知类型或无有效金额时不显示、不从物品名称猜测。角标仅说明门槛和金额，不表示当前购买满足品类、时间等使用条件。有到期时间条时角标下移避让；不会拦截道具鼠标事件。
- 保留完整 `bagDatas` 给原生背包增删更新，只过滤绘制和分页。当前挂载实例的方法与原生已注册的事件回调一并包装；隐藏、关闭、停用、重载和卸载恢复方法并清理控件、主题订阅及快捷键，无购买、使用或丢弃操作。
- 核心0.5.142增加公共抵价券配置表白名单，仅打开背包后按需读取，沿用核心现有官方配置解码与缓存。旧版本核心不支持该表，因此最低版本同步提升。

## 面板

- 重要物品展示官方图标、当前余额，以及本次登录观察到的收入和消耗。元宝、传世玉玺、玉玺碎片、绘卷毛笔和秘钥（用户所称“密钥”）来自官方物品配置；当前余额未知时显示“未知”，不写成0。
- 收入与消耗分别累计：先收入100再消耗100，仍显示“收入+100 / 消耗−100”。相同名称按物品基础ID分开计算；不根据名称合并。
- 祈福活动以现存NewBlessManager.IsInDrawTime判断。祈福周内显示当期exgoodsid，并保留仍持有、未明确过期的上一期如意结，逐行显示ID；非祈福周整体隐藏。活动或配置尚未就绪时不假定正在祈福。
- 祈愿台按活动和龙珠物品ID累计本次登录确认次数，列出已关联奖励；未收到奖励或存在多个关联候选时明确标为待核对，并列出未关联奖励。
- 插件启用后通过核心按需读取公共物品、ff_qifu_new和ff_tiangong配置。插件启用即开始被动观察，不因折叠、切换分类或关闭详细页而停止。没有抽奖、购买或领奖操作。

## 详细页面与存储

「详细账本」由用户点击打开新页面，可按开始/结束时间、物品名称或完整ID、登录范围、物品流水/祈愿台筛选。每页100条，日志可完整展开；支持将筛选结果导出JSON。原始消息名、原因代码和去重依据放在具体日志中，不保存完整协议、账号凭据或登录对象。

日志保存在当前浏览器的IndexedDB：数据库`sgs-toolbox-ledger-v1`，对象仓库`records`，主键`id`，索引`account`。每条记录包含account、session、at、kind、source，以及投影后的items/祈愿信息；按账号读取，不设置静默截断或自动清理。浏览器清除站点数据会删除历史；空间不足或数据库错误会保留当前页内存、报告完整错误，并可先导出。

同一页面内停用/重新启用或插件升级保留会话标识并提示采集中断；重新登录、账号变化、整页刷新开始新的观察会话。历史仍按账号保留。首次启用无法追回本次登录早先的变化，界面始终注明“仅含已观察变动”。切换账号立即隐藏旧日志和余额，等待新账号的背包基线/货币通知后再显示余额。停用/卸载会释放所有原生监听、定时器、页面事件与主题订阅；不删除本机历史。

## 协议依据与边界

静态核对旧小抄1.6.74账本及本机缓存客户端，不运行旧脚本后台逻辑。REA分析旧发布包的外层图后，对嵌套字符串作隔离解码，只执行字符串表和索引解码器；静态推断不代表已观察到官服消息。

- 旧脚本`yh`将本次收支净额合并且过滤净额0，本插件改为分方向累计。
- `DbsCcUserGoodshintNtf`：仅读取Type、GiverNickname和GoodsList中的GoodsBaseID/ChangeCount，作为到账记录。元宝使用独立货币流，避免同一元宝到账被两个来源重复统计。
- `DbsCUpdatauserYaunbaoNtf`：ChangeYB为元宝变化，Why为原因；余额读取当前self.YuanBao。余额改为self.YuanBao + self.BindYuanBao + self.FreeLimitYuanBaoNum；任一分量未知时总额未知。流水仍仅统计已观察到的通知，不从余额净差伪造分方向收支。
- `DbsCcUserGoodslistRep`：ID/BaseID/Count建立实例基线，列表初载或重发不记为收入。`DbsCcUpdategoodsAttribNtf`按GoodsID定位基线计算Count差值；数量0同样处理。`DbsCcUserDelgoodsNtf`仅Result=1时计算PropID实例移除的消耗；缺失基线时提示缺口，不猜数量。
- 到账通知与实例差值在8秒内按基础ID、方向、数量消费匹配，避免双记；支持两种到达顺序，不合并同一来源连续相同金额的真实操作。两路消息没有事务ID，此关联属于有限窗口推断，不能证明任意延迟/交错下的全局完备性。
- 祈愿台成功回包120004实际通过`decodeClientSecretExploreRep`事件分发（不是字符串数字事件）；protobuf字段为secId、times、result，result=0计次数；外层路径为Protocol.Data.ProtoObj。配置Common.Id/Name/Itemid确定活动与龙珠。奖励来自物品通知Type2010。15秒内两路各有唯一候选才关联，日志保存关联依据；奖励和次数之间没有强事务ID，不强行配对并发候选。奖励的余额收入仅计一次。
- 原生监听投影后异步消费；队列溢出、代理重绑、未知实例等均提示记录缺口。停用期间不补记、不推算。
- 图标优先使用原生物品VO的ItemSmallIconUrl；未持有物品从已知原生图标提取当前资源根地址，结合官方PicID构建相同资源路径。元宝沿用原生BigGiveBuy/70路径，不写死某个客户端发布目录。余额不依赖图片是否加载成功。

## 上线数量预警（0.2.0）

物品列表在有增减时显示本次上线首次有效数量相对上次在线最后有效数量的增减。在默认收起的「预警设置」中逐物品、逐账号设置减少阈值，0表示关闭；减少数量大于等于阈值时立即弹出主题化提醒，即使账本面板关闭也生效。同次登录每种物品只提醒一次，关闭后不会反复弹出；同次登录比较结果保持不变。首次使用只建立基线，无历史或未知数量不推算为零。

最后有效余额持续被动保存到插件账号设置（balance:账号），阈值为threshold:账号:基础ID；同页热重载保留比较及已提醒状态。重新登录后等待账号基线；刷新页面视为新观察会话。只保存本浏览器所观察到的数量，停用期间无法更新基线，其他设备及清除站点存储后无历史可比。如意结仅在可确认的祈福活动期间参与。配置在插件启用后按需加载以支持后台预警，不需打开面板。

### 0.2.1 精简与预警口径

移除逐物品常驻阈值输入及重复的无历史提示，阈值集中在「预警设置」。上次有效观测时间超过7天不告警；余额未变化时也每30秒更新最后观测时间。玉玺碎片不单设阈值，与玉玺按10片=1枚合并比较，合并阈值支持0.1枚；两项基线均有效且都在7天内才告警。单项实际库存和流水仍分别展示。元宝余额与预警合计普通、绑定、限时三类；旧普通元宝基线不混用，升级后首次建立新口径基线。

12项账本单测及浏览器演练通过；客户端余额字段依据现有tests/fixtures/seckill-client.json的客户端购买校验片段。离线演练不代表官服实局验收。

### 0.2.2 预警范围与界面

仅元宝、玉玺合计、绘卷毛笔、秘钥四项支持阈值预警。如意结不参与阈值判断，旧版保存的如意结阈值不再生效，不修改其余额和收支记录；玉玺碎片仍合并折算。预警设置显示启用项数，输入框带单位，规则集中说明；压缩观察说明和如意结ID，保留悬停完整信息。核心0.5.58同步打包。

### 0.2.3 祈福灯与默认额度

重要物品和预警增加祈福灯，使用官方物品配置按名称解析基础ID，不猜测或写死活动ID。默认减少阈值：元宝5000、玉玺合计10枚、祈福灯30个、绘卷毛笔50个、秘钥50个。默认值仅用于未设置过的账号物品；已有自定义值和显式0（关闭）保持不变。七天有效期、碎片折算及如意结不告警规则不变。演练中的祈福灯ID和图标仅为合成布局数据。

### 0.2.4 刷新启动修复
游戏配置解码器或资源版本尚未就绪时，账本每两秒在后台重试，不再把正常启动等待上报为运行错误，也不依赖打开信息栏触发恢复。配置损坏、网络读取及数据库错误仍保留完整详情；停用后不再重试。模拟冷启动、取消和真实配置失败回归通过；尚未完成官服刷新验收。

### 0.3.2 背包增删刷新修复（核心 0.6.10）

背包增强不再替换 `onAddBagItem/onUpdateBagItem/onDelBagItem` 或修改物品管理器中已注册的 Handler.method。原生 on/off 依赖函数引用一致，且 Laya Handler 会回收复用；插件包装会破坏关闭、重开时的监听身份与清理边界。

保留原生增删更新链路，在现有 500ms 背包检查中比较物品实例、数量、标记、有效期及名称等字段；变化后重新计算搜索分页并绘制当前列表。只读完整背包数据，不发送刷新或物品操作请求。停用时仍恢复原始列表绘制。
