# 好友与聊天

## 0.1.5：自动取得官阶资料、同步换行高度

本次包含前一轮本地0.1.4的原生官阶服务、图片预加载和诊断改动，并处理用户继续反馈的“需要点一下昵称才出现”和“分行后尾行被盖住”。

- 原生 `OfficerManager.GetOfficerChatIcon` 从现有 `ClientOfficerInfoRep/ClientOfficerUpgradeRep/ClientOfficerSimpleInfoRep` caller定位，不依赖类名可见或重新解密配置；没有现成服务时保留官方配置路径。官阶图片先通过原生加载器就绪再插入HTML，防止未缓存图片首次布局宽度为零；不销毁官方共享纹理。
- 不能把缓存的ClientId和默认OfficerLevel视为完整资料。现在每个已识别昵称每登录最多自动调用一次原生 `SendUserDetailReq(name,false)`，保留客户端180秒冷却，每秒最多一人、每账号最多256名；未知昵称通过原生 `CreateNickNameInstance/SetInstance` 登记，和原生菜单首次请求保持一致。不打开菜单，不强制绕过冷却，不上传或本地持久化详情。尚未初始化的默认官阶不作为确定结果；响应到达后由原有轮询补图标。所有昵称仍保留原生点击行为。
- 改写HTML后先同步 `layout()` 再按原生 `aJi.Size(width,contextHeight)` 更新行高。后续即使HTML未变化，也检测延迟完成的排版高度；按原生消息顺序重排后续行，避免第二条覆盖第一条的 `*1` 等尾行。自然长消息仍可换行，不强制单行截断。原本位于底部时保持跟随，用户上翻时不主动跳到底部；停用还原HTML后同样重算位置。
- 「工具 → 好友与聊天」新增聊天状态与「导出聊天诊断」，仅含消息数、链接数、已获资料数、显示图标数、原生服务/配置状态和图片加载/失败数，不含聊天内容、昵称或用户ID。

## 0.1.3：好友菜单首帧定位

原先在500ms轮询发现已显示的好友菜单后才插入置顶行，原生 `layoutBtn → ResetOptMenuPos` 重新测量后可能跨过屏幕边界并改放置位置，造成可见跳动。现在定位现有提示层实例，包装它的 `addChild`：原生 `LKi.ShowUserOptMenu` 创建菜单并添加、定位、调用 `ShowOptMenu` 的同步流程中，在添加菜单前绑定该实例，使置顶行参与第一次正式布局；不修改原型，不额外创建原生单例。

提示层为空时 `GD` 会把它从显示树移除，因此除显示树外，还按当前场景现有 `ged` 的 `SHOW_TEXT_PROMPT/SHOW_COMFIRM_TIPS_EVENT` 精确caller定位，覆盖第一次点击。若插件启用/发现时菜单已经显示，则只绑定下次 `ShowOptMenu`，不当场扩高或重新定位。正式好友菜单预留一行，资料未就绪时禁用置顶按钮，资料到达只更新状态，避免中途增加高度。既有菜单销毁、扁平文字清理和账号隔离仍保留。

## 0.1.2：密码房输入与原生系统消息官阶

- 原生 `SM.htmlStyleLink` 使用 `<font href>`，不是此前模拟的 `<a>`。现在两种标签都识别，保留原标签、链接、样式和文字；系统消息将已编码昵称再次编码时，只有二次解码与可见昵称一致才采用，避免误解码昵称中的字面百分号。同时检查原生显示容器的 `contains`，补齐扁平列表发现路径。
- 已在大厅原生 `HallManager.getTableInfoByID` 中确认 `HasPass` 的房间，点击直接调用现有 `RoomControler.Ged._('ShowPwdWindow',caller,callback)`，不发送空密码。未知房间仍由服务器检查，但仅将插件这次空密码请求产生的 `PASSWORD_ERROR_EVENT` 转为输入窗口，不弹首次密码失败；之后用户填写错误密码仍遵循原生提示。密码确认使用原生 `joinTableWithPwd` 参数，密码不持久化、不导出。
- 首次请求的拦截最多8秒；手动进房、观战或离房、账号/模式变更、进入房间/牌局、停用均撤销拦截或使旧密码回调失效，不接管其他进房错误。

## 0.1.1：原生菜单文字重影修复

修正原生好友菜单的置顶按钮释放方式。游戏 `Djt.getBtn()` 返回 `$jt/EO` 扁平按钮，没有普通 Laya Sprite 的 `destroy()`；它的文字命令直接存放在菜单 `graphics` 中。旧实现菜单离开显示树时调用 `destroy(true)`，释放抛错并留下旧按钮的文字命令，再打开菜单创建新按钮时可能叠画。现在调用现有菜单的 `removeDrawChild(button,true)`，沿原生 `EO.clear` 和 `CO.clear` 清掉绘制命令、事件与扁平容器登记；普通Sprite演练环境仍按对应节点接口释放。置顶文字未变化时不重复赋值。

独立插件 `social`，版本 0.1.5，最低核心 0.5.13，无前置。随插件启用生效，操作入口直接位于游戏原生好友和聊天界面；「工具 → 好友与聊天」保留完整改名记录与导出。

功能范围：公屏聊天识别短房间号并提供点击进房；原生好友菜单置顶与取消置顶，使用稳定用户 ID；按账号定时保存好友 ID 和昵称，提示可能改名；为各频道的可点击用户补官阶或机器人标记。

置顶数据及好友快照属于本机当前登录账号，不上传，不按昵称关联账号。停用保留持久化数据并释放轮询、监听和实例包装。机器人采用已有玩家信息功能的账号范围启发式，不能当成官方认证。

## 行为与数据

- 房号识别完整的1–5位正数字段，不截取长用户码中的一段；每条普通发言最多提供8个候选链接。点击按当前模式和分组编码，调用现有 `RoomControler.SendJoinTable`，不把裸房号当完整房间 ID。模式未知时等待；进行中或状态未知的牌局须先使用游戏原生退出流程，明确未开局的房间可单次退出后等待大厅进房，8秒超时保留结果未知。账号/模式变化及停用取消待处理任务。
- 仅正式好友 `GroupID=1` 支持置顶；新申请和黑名单不受影响。同为置顶或普通好友保留原生排序。原生会员角标被置顶图标替代，非会员也有置顶图标；取消、停用及账号切换恢复原生显示与排序。
- 原生 `friendID` 为单字节槽位，不能作稳定身份；从好友 `userData.ClientId` 或原生 `UserData.GetNameInstance` 缓存取真实用户码，按10位字符串保存。资料缺失时每500ms最多查询一名好友，每登录每昵称只请求一次；缺少 ID 不置顶、不比较改名。
- 快照首次及发现变化立即保存，稳定时每60秒保存。存储键 `friends:<当前账号10位ID>`，格式 `{version:1,pins,friends,changes}`；`friends[id]={name,seenAt}`，`changes=[{id,from,to,at}]`。基线与变化仅在成功写入后提交，每次变化只提醒一次；刷新不会重新提醒已记下的变化。最多保存2000位已观察好友、200条近期变化，不把快照说成完整实时好友列表。写入失败保留原基线与完整错误；卸载不自动删除历史。
- 所有识别到的原生可点击用户名（含综合、公会及系统提及）保留原链接，并补真实官阶图标，包含低于偏将军的官阶。原生 `h5_officer` 配置决定图标路径，不能取得资料时不猜官阶。机器人使用 `ClientId>4000000000` 的启发式标记。聊天资料只在运行期使用；缺资料每秒最多查询一名、每账号最多256名，不重试。官方配置失败最多3次、间隔10秒。
- 面板只读显示当前账号记录，可完整查看长昵称和存储错误，以JSON导出当前账号好友、置顶和改名记录。数据不上传，查询仅使用游戏原有基础资料协议。独立插件启停可控制全部增强行为，没有额外自动业务开关。
