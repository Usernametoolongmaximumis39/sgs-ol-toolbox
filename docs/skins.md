# 皮肤收集插件 0.3.5

功能直接集成游戏的「皮肤管理」。从 0.4.4 起不再注册工具箱 HUD 面板或显示接入状态，所有功能直接在游戏皮肤管理中使用。插件 ID 仍为 `skins`，不依赖其他插件或旧小抄。

## 筛选和统计口径

| 项目 | 口径 |
| --- | --- |
| 静态已拥有 | 当前背包中该皮肤有正数量，包括限时皮肤；不表示永久拥有 |
| 动态类型 | 无动态 / 需解锁动态 / 自带动态 / 类型未知；自带动态包含客户端自动解锁款，不因旧升级配置或水晶商品而改为需解锁 |
| 动态拥有 | 未拥有动态 / 已有动态 / 状态未知；无动态的款式不计入“未拥有动态” |
| 可朱砂升级 | 动态支持用朱砂解锁；不读取或比较朱砂余额，不要求先拥有皮肤或动态未解锁；已拥有等条件通过其他组独立限制 |
| 仅水晶升级 | 动态不能用朱砂解锁、只能用专属水晶；与“可朱砂升级”互斥 |
| 水晶准备 | 已有水晶 / 缺少水晶，面向尚未拥有动态的款式；包括尚未获得皮肤的款式，可叠加底部静态状态限制 |
| 方式未知 | 动态存在但解锁方式缺乏可靠数据，不擅自归为自带动态或仅水晶 |
| 筛选了 / 已拥有皮肤 | 当前结果内的皮肤种类数和已拥有种类数；新品、新获得、特惠重复出现的同款只计一次 |
| 动态 / 已拥有动态 | 当前结果中有动态版本的种类数及已解锁种类数，自带动态的已拥有皮肤计入后者 |
| 原皮 | 只在无搜索、无状态筛选的势力分类中显示；品质分类、所有筛选和统计均排除 |

**包含规则：能用朱砂升级的，必定也支持水晶升级。** 因此不再把“可朱砂升级”和“可水晶升级”并列；前者属于支持水晶的大类。皮肤本体能否合成与动态解锁方式完全独立，不读取本体合成条件来判断动态。

常用组合：

- 看没有动态的皮肤：动态类型选“无动态”，其他动态组不限。
- 找能朱砂解锁的动态：解锁方式选“可朱砂升级”，朱砂余额不影响结果。
- 找已有皮肤但动态未解锁且缺晶的款式：静态选“已拥有”，动态拥有选“未拥有动态”，水晶准备选“缺少水晶”。若只找无法用朱砂替代的款式，再选“仅水晶升级”。
- 找水晶已备齐但动态未解锁：动态拥有选“未拥有动态”，水晶准备选“已有水晶”。
- 看自带动态：动态类型选“自带动态”，其动态拥有状态跟随皮肤是否拥有。

完整背包未就绪或切号时显示等待，不把账号未知状态当成未拥有；单款异常数据保留未知。库存及账号不落盘，只保存分类偏好。新获得列表只读取原生记录，不额外清除“新获得”；原生卡片自己的查看 / 鼠标离开行为保持原样。

- 顶部两种分类共用一套红底金边标签，去掉品质模式的小圆章与重复字样；新品固定在相同位置，其他标签保持相同宽高和点击区域。
- 原生国家页数据和点击逻辑继续保留；自绘导航同步新获得红点/数量。停用恢复原导航与新品动画原可见状态。
- 内容标题降低高度，优先读取原生卡片的 flagTet.texture，直接复用品质角标且不重着色。没有可用图案时才使用卷纹金属标题；普通为银白，限定为金边红底，避免圆章与卡框风格冲突。
- 原0.2.1圆章素材只作为历史美术资料保留，不再引入发布包。

## 接入与恢复

- 在已经存在的皮肤管理实例上接入；不创建游戏窗口、管理器或账号单例，不替换全局皮肤配置。
- 使用原生 `formData` / `selectGenerals` 生成模型，保留原生势力内容行与新品 / 特惠绘制方法。品质模式覆盖五档并纳入 Q 版皮肤；按客户端国家列表补上晋的条目。
- 同一份数据上的搜索、品质切换和拥有状态切换不重复生成全部模型。物品更新、重新打开窗口及切号时刷新；停用、重载、卸载会移除控件和监听、恢复搜索位置与原生方法。后装插件包裹了本插件方法时，停用后的本层也会透传原生调用。
- 保持原生皮肤详情、制作、升级和分解操作；插件本身不发送这些操作请求。
