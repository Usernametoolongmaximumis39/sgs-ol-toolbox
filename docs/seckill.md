# 自动秒杀插件

入口为工具箱「自动 → 自动秒杀」，稳定 ID `seckill`。可独立安装，只依赖核心 `0.5.13` 及以上；不需要旧小抄、旧拓展或日常领奖插件。总开关默认关闭，未设置时预选功勋和皮肤包，其他预置目标不选；不会导入旧拓展的全局购买开关。

开启会购买商品并扣除对应游戏货币。先选择预置目标或添加自定义关键词，再开启总开关。商品列表中的「优先」可临时指定本场商品，仍受总开关控制；取消优先会暂停自动购买十分钟。关闭总开关或停用插件立即停止后续查询和购买，已经发出的服务器请求不能撤回。核心折叠只隐藏面板，不停止任务。

- 绘卷毛笔：名称含毛笔，3 支装；龙珠：名称含龙珠，5 个装；普通/奇珍夺宝券均为10张装，普通夺宝券排除奇珍夺宝券。
- 祈福灯：10个装、6666元宝（`price_type===2`）。新增货币核对，避免同价的通用元宝或银两商品被当作目标。
- 功勋、皮肤包、招募令不限数量；自定义关键词最多20项，每项24字符，去空白/小写匹配，自动套用对应的数量和价格规则。自定义短词可能匹配多个商品，开启前可在商品列表查看已选状态。
- 商品必须具备明确身份、名称、货币、价格、数量、售卖时间、库存和个人限购数据。未知状态不购买。限购0代表不限，库存0代表售罄；未知与0分别显示。
- 当前可售目标优先于未来目标，然后按开抢时间排队。每300ms检查，不在开抢前发送购买。发送前重新核对活动身份、商品、价格、数量、库存、限购和售卖时间。
- 明确失败的请求至少间隔300ms，每轮3次，轮间30秒，最多3轮9次；换场或商品内容实质更新可重排。库存数字或勾选状态变化不重置次数。成功后冷却3秒，然后处理下一件。
- 没收到回包时不会把超时当失败继续扣款：1200ms后显示「结果未确认」，查询库存核实，每30秒最多补查一次。匹配的成功回包（15秒内，且只有一个未确认目标）或原生个人购买数增加才确认成功；无关回包、普通列表更新、提示文字和已发送请求均不当作成功。
- 未确认的商品从列表消失后仍保留记录，并阻止相同基础物品的新活动重复购买；其他基础物品可继续排队。不会静默清除无法核实的扣款。
- 按北京时间0/8/12/19点换场：立即重查，并在10秒后补查；平时每10分钟重查一次，即使旧列表为空也会查询。已购买的相同行身份保留，未来场次用新的活动/商品/开抢时间区分。
- 配置、购买/重试/未确认记录和冷却以账号隔离，持久化于插件命名空间。最多保留512个商品身份，不丢弃未确认请求来腾出位置。换账号清空界面；原生列表须重新同步才能购买。账号的第一次使用默认关闭。

这些是本地脚本核查、受控客户端模型回放和浏览器演练，尚未在官服实际扣款抢购中验收，不承诺库存竞争结果。建议官服先检查商品名、价格、数量和选中状态，再启用。旧脚本后台不会因界面隐藏而停止，实际启用新插件时应关闭旧脚本的秒杀任务，避免两个购买循环并行。

未设置时预选功勋、皮肤包，其他商品不选；自动购买总开关仍关闭。已有商品显式设置优先。
